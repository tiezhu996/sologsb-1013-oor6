# 舞台演出串联与提示表编辑器

导演和舞台监督使用的纯前端提示表工作台。可按幕、场和提示点维护演出流程，拖动后自动顺延后续时间，并持续检查负责人、时间、道具、演员和引用关系。

## 功能

- 按幕、场维护开场时间、灯光、音响、道具、演员、负责人和工作备注。
- 顶部登记当前跟场人，换班时直接改名交接；侧栏显示本场已签核进度。
- 每条提示有「待执行 / 进行中 / 已完成」签核状态，提示行和详情面板都能一键切换；记录操作人与开始、完成时间，并保留完整签核/撤回日志。
- 同一场内必须前一条完成签核后才能开始下一条；撤回时后续若已有进行中/已完成提示会被拦住。
- 提示点原生拖拽排序；签核记录跟随提示移动，若新顺序让完成记录落到未完提示之后会拦截并说明原因；调整后自动重算当前场后续提示时间。
- 检查负责人空缺、同场时间冲突、跨场道具撞场、演员撞场及已删除提示的失效引用。
- 复制上一场完整流程，并自动生成独立提示 ID（签核记录重新开始）。
- 锁定场次或保存锁定版本，从历史版本建立可编辑修订。
- 选择锁定版本后按提示逐条比较负责人、时长、流程与签核状态变化。
- 文档级撤销/重做、键盘顺序调整、搜索和浏览器本地持久化（签核随提示表一起离线保存）。
- 可交互的首演示例数据覆盖两个场次、多类提示、签核进度和待处理问题。

## 技术栈

- Ember 5
- TypeScript
- Ember Paper
- Glimmer 组件
- 原生 `localStorage`

## 本地开发

```bash
npm install
npm start
```

浏览器打开终端输出的开发地址。

## 生产构建

```bash
npm run build
```

生产文件位于 `dist/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `Alt + ↑ / ↓` | 将当前提示前移或后移 |
| `N` | 新建提示（表单编辑区域外） |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |

## Docker

容器内由 nginx 监听端口 `80`，源码不硬编码宿主端口。

```bash
docker build -t stage-cue-prompt-editor .
docker run --rm -p 10013:80 stage-cue-prompt-editor
```

宿主端口 `10013` 仅作为本地运行示例，实际端口由根编排文件统一管理。
